    What's here

    data

    21,484 records spanning ARM (NEON / Helium / SVE / SVE2 / SME) and Intel (MMX / SSE* / AVX / AVX2 / AVX-512 / AMX) — plus 208 SIMD types. Each entry has signature, ISA family, arch, short prose description, and (where upstream provides it) pseudocode.

    Thousands of entries also carry a worked example with editable inputs: deterministic input vectors, the verified output, and a "↻ run on CE" button that recompiles your edits live on Compiler Explorer.

    Generated automatically from upstream sources (ARM ACLE, Intel Intrinsics Guide XML, LLVM clang headers). Pure stdlib Python, no LLM in the loop.

    Examples (click): vaddq_s8 · _mm_min_epi32 · vqtbl1q_u8

    simd-tooltip

    Drop-in JavaScript tooltip library — one <script> tag adds hover (or click, or hover-with-?-badge) tooltips to any HTML page. Detects intrinsic names in text on the fly using caretPositionFromPoint — no DOM walk, no markup mutation by default.

    ~22 KB minified, ~7 KB gzipped. Lazy-loads the data file on first hover.

    Examples (hover): vaddq_s8 · _mm_min_epi32 · vqtbl1q_u8

    simd-annotate

    A CLI that takes any static HTML file, scans the visible text for intrinsic and type names, and emits a self-contained, 100% offline HTML file with the library plus only the slice of the database the page actually references embedded inline.

    Useful for archived posts, e-book exports, intranet docs. Pure stdlib Python.

    Example: original / annotated

    simd-vscode

    VS Code extension that surfaces the same data as a hover tooltip directly in your editor. Covers all ~22k intrinsics, including the AVX-512 and ARM NEON / SVE / SME ranges where clangd typically shows only the bare signature.

    Manual install via vsce package + code --install-extension for now.

    simd-browser-extension

    Browser extension (Chrome & Firefox, MV3) that brings the same hover tooltips to any webpage — GitHub PRs, blog posts, mailing-list archives, intranet docs. Bundles the database offline; no per-page setup, no network calls.

    Options: master enable toggle, intrinsics-only vs also-show-types, and a per-URL exclude-regex list. Manual install for now (Chrome "load unpacked" / Firefox about:debugging); store-published builds to follow.

    Why this exists

    SIMD code is high-leverage but easy to forget. Every codebase that uses _mm256_fmadd_ps, vqtbl1q_u8, or svadd_s32_z is a codebase whose readers — including its future authors — periodically stop and look up what the intrinsic does. The reference material exists (Intel's Intrinsics Guide, ARM's developer portal, the ACLE spec), but none of it embeds well into a third-party blog post or a code review or an in-editor hover.

    So this project takes the reference material that already exists, hammers it into a clean open database, and adds three thin presentation layers so you can drop intrinsic-aware tooltips into any context that takes plain HTML, plain text, or a VS Code workspace.

    Related projects

    • Compiler Explorer has rich hover tooltips on the assembly side, but nothing on the C/C++ source side. Our database covers the source side.
    • clangd has rich Doxygen for ~15% of Intel intrinsics (mostly SSE/AVX/FMA) and signature-only for AVX-512 and almost all of ARM NEON/SVE/SME. simd-vscode fills the gap.
    • Intel's Intrinsics Guide is the upstream we already pull pseudocode from. Beautiful for browsing but you can't embed its tooltips on third-party content.
    • simd.info is a much deeper paid reference with a different focus (reading rather than embedding). Not open.
    • Highway's g3doc/ has hand-curated writeups that mention intrinsics inline — kindred spirit but manually maintained.

    Source on GitHub. Database content from ARM ACLE (CC-BY-SA-4.0), Intel Intrinsics Guide, and LLVM clang headers (Apache-2.0 with LLVM exception); see the project's NOTICE.

    Per-intrinsic asm: MNEMONIC → links point at Felix Cloutier's x86 reference (a clean HTML mirror of the Intel SDM); perf: MNEMONIC → links go to uops.info for measured per-microarch latency / throughput / port distribution (Intel + AMD).

    Intrinsic pages also carry an asm perf table: Intel intrinsics show Intel's own per-microarch numbers (Alder Lake / Ice Lake / Sapphire Rapids / Skylake) lazy-loaded straight from the iguide's perf2.js; ARM intrinsics show numbers derived from LLVM's AArch64 scheduling models via llvm-mca --instruction-info. Both load only when you visit an intrinsic's dedicated page.
